Note de vocabulaire : Claude Code embarque srt pour son « bac Bash » ; srt se lance aussi seul (`srt <commande>`, ou `npx @anthropic-ai/sandbox-runtime claude`) pour confiner tout le processus Claude Code [S1 « Sandbox runtime »] [S2 l.36].

1. **Ce qui est confiné.** Le bac Bash couvre les commandes des outils Bash, PowerShell et Monitor et leurs processus enfants [S2 « What the sandbox restricts »]. Il ne couvre pas les outils fichiers et web intégrés (Read, Edit, Write, WebFetch, soumis aux seules règles de permission : un `denyRead` n'arrête pas Read), ni les hooks, serveurs MCP locaux, moniteurs de plugin, serveurs LSP, ligne d'état, `apiKeyHelper`, ni les processus lancés par un « mod » [S2 « What runs outside the sandbox », « Scope »]. Sortent aussi du bac : ce que l'humain tape après `!`, les commandes qui correspondent à `excludedCommands`, et les reprises « hors bac » demandées par le modèle [S2 même section]. Pour mettre tout le processus derrière une frontière, la doc renvoie à srt, au dev container, à un conteneur ou à une VM [S1 tableau « Compare sandboxing approaches »]. Côté srt : sous macOS un profil SBPL généré à chaque commande, qui commence par `(deny default …)` puis autorise `process-exec`, `process-fork`, une liste fermée de services Mach, de `sysctl` et d'IOKit [S7 `macos-sandbox-utils.ts:1075-1247`], appliqué par `env … /usr/bin/sandbox-exec -p <profil> <shell> -c <commande>` [S7 `macos-sandbox-utils.ts:1585-1596`] ; sous Linux, bubblewrap avec `--new-session --die-with-parent` [S7 `linux-sandbox-utils.ts:3334`], racine `--ro-bind / /` puis `--bind` des chemins inscriptibles [S7 `:2193-2257`], `--unshare-net` [S7 `:3419`], `--unshare-pid`, `--unshare-user`, `/proc` neuf [S7 `:3530-3553`], et un filtre seccomp qui refuse `socket(AF_UNIX)` et `io_uring` [S7 README l.966-990]. Le réseau passe par un mandataire HTTP et un SOCKS5 lancés hors du bac : port local unique autorisé par le profil sous macOS [S7 `macos-sandbox-utils.ts:1311-1337`], sockets Unix reliés par `socat` sous Linux [S7 README l.836]. La lecture est permise partout par défaut ; l'écriture est refusée partout sauf liste [S7 README l.119-120].

2. **Droits.** Déclaration : clés `sandbox.filesystem.allowWrite/denyWrite/denyRead/allowRead`, `sandbox.network.allowedDomains/deniedDomains`, `allowUnixSockets`, `allowLocalBinding`, fusionnées sur toutes les portées de réglages, et complétées par les règles de permission (`Edit` → écriture, `Read` deny → lecture, `WebFetch(domain:…)` → réseau) [S2 « Permission rules »] [S3 `sandbox.filesystem`]. srt seul lit `~/.srt-settings.json` ou `--settings` ; absent, il démarre avec ses défauts (pas de réseau, écriture limitée à `/tmp/claude`, `~/.npm/_logs`, `~/.claude/debug`) ; présent mais vide ou invalide, il refuse de démarrer [S1 « What the runtime blocks on its own »] [S7 README l.177-185, l.532]. Découverte d'un droit manquant : pour le réseau, Claude Code nomme l'hôte refusé dans le résultat de la commande et, selon le mode, pose la question à l'humain ; « Yes » vaut pour la session, « Yes, and don't ask again » écrit une règle `WebFetch(domain:…)` dans les réglages locaux [S2 « Network isolation », « Hosts outside your allowed domains »]. En mode auto, le modèle déclare les hôtes sur la commande elle-même et un classifieur les juge, pour cette seule commande [S2 « Per-command allowed domains in auto mode »]. Pour les fichiers, srt joint à la sortie d'erreur un bloc `<sandbox_violations>` tiré du journal des refus [S7 `sandbox-manager.ts:2854-2875`] : sous macOS par `log stream` filtré sur un suffixe de session placé dans le message du `deny default` [S7 `macos-sandbox-utils.ts:146-155, 1621-1644`] ; sous Linux par un observateur seccomp `USER_NOTIF` qui ne voit que les écritures [S7 `linux-violation-monitor.ts:20-30`], les lectures refusées restant invisibles [S10]. La doc ne décrit aucun mode « apprentissage » qui transforme un refus de fichier en `allowWrite` proposé ; la réponse documentée à un échec est la reprise hors bac (`dangerouslyDisableSandbox`), approuvée selon le mode de permission [S2 « The unsandboxed retry escape hatch »]. Qui accorde : l'humain à l'invite ; l'administrateur par réglages gérés. Quand l'administrateur rend le bac « admin-required » (`allowUnsandboxedCommands: false` géré ou en `--settings`, ou `allowManagedDomainsOnly`), Claude Code ignore les clés qui élargissent le bac dans `.claude/settings.json` et `.claude/settings.local.json` du dépôt : `excludedCommands`, `allowWrite`, `allowedDomains`, `ignoreViolations`, `enableWeakerNestedSandbox`… [S2 « Repository settings under an admin-required sandbox »]. Certaines clés ne sont jamais lues dans un dépôt : `filesystem.disabled`, `allowAppleEvents`, les masques de secrets, `tlsTerminate`, `strictAllowlist` [S2 « Which settings can disable it », « Mask credentials »] [S3 `sandbox.allowAppleEvents`].

3. **Refusé quoi qu'on déclare.** srt refuse toujours l'écriture de `.gitconfig`, `.gitmodules`, `.bashrc`, `.bash_profile`, `.zshrc`, `.zprofile`, `.profile`, `.ripgreprc`, `.mcp.json`, des dossiers `.vscode/`, `.idea/`, `.claude/commands/`, `.claude/agents/`, de `.git/hooks/`, et de `.git/config` sauf `allowGitConfig` [S7 `sandbox-utils.ts:12-41`, `macos-sandbox-utils.ts:100-133`, README l.914-938]. Sous macOS ces refus sont des motifs vérifiés à l'écriture, donc valables pour un dépôt créé pendant la commande ; sous Linux la liste est construite une fois au lancement par un parcours `ripgrep` limité à `mandatoryDenySearchDepth` (3 par défaut), et ne couvre pas ce qui apparaît ensuite (`git init`, `git clone`) [S1 « What the runtime blocks on its own »] [S7 README l.948-962]. Claude Code ajoute ses « chemins protégés » : réglages et dossiers `.claude/*` du répertoire de travail et de ses parents, `.gitconfig` et fichiers de démarrage du shell du répertoire de travail, ce qui ferait de lui un dépôt nu (`HEAD`, `objects`, `refs`), et `~/.claude` ; aucun `allowWrite` ne lève cette protection, seul `filesystem.disabled` la supprime [S2 « Protected paths »]. Il n'existe en revanche aucune liste intégrée de secrets à ne pas lire : `~/.ssh` et `~/.aws/credentials` sont lisibles tant qu'on ne les déclare pas [S2 tableau « What the sandbox restricts », « Protect credentials »]. Le mandataire refuse un nom autorisé qui se résout vers une adresse locale (boucle locale, lien local dont `169.254.169.254`, adresses de la machine) [S2 « Hostnames that resolve to local addresses »] [S7 README l.463-467]. Sous Linux, création de sockets Unix refusée par seccomp [S7 README l.966-990].

4. **Environnement de l'hôte.** Les variables d'environnement sont héritées par défaut, secrets compris [S2 tableau « What the sandbox restricts »] : sous macOS la commande passe par `env` avec seulement des `-u` pour les variables refusées [S7 `macos-sandbox-utils.ts:1572-1596`] ; sous Linux par `--unsetenv` [S7 `linux-sandbox-utils.ts:3387-3396`] ; aucune liste blanche. srt pose `SANDBOX_RUNTIME=1` et `TMPDIR=/tmp/claude` (ou `CLAUDE_CODE_TMPDIR`) [S7 `sandbox-utils.ts:758-771`]. Pour les secrets : `sandbox.credentials` en mode `deny` (fichier illisible, variable retirée) ou `mask` (sentinelle dans le bac, vraie valeur réinjectée par le mandataire vers les hôtes permis, TLS terminé exigé ; sous macOS un fichier masqué devient simplement illisible) [S2 « Protect credentials », « Mask credentials »] [S7 `macos-sandbox-utils.ts:1436-1454`]. `CLAUDE_CODE_SUBPROCESS_ENV_SCRUB=1` retire des sous-processus les variables qui ont l'air de secrets, mais laisse `GITHUB_TOKEN`, les mandataires et `GIT_CONFIG_*` [S4]. Configuration git : rien ne l'isole. La lecture de `~/.gitconfig` est permise par défaut, et même sous `blockReadsOutsideWorkingDirectories` Claude Code la rouvre exprès, avec `~/.config/git/*` et les fichiers inclus, « so git keeps your identity and settings » ; seuls `~/.git-credentials` et `$XDG_CONFIG_HOME/git/credentials` restent fermés [S3 « Sandboxed commands under the block »]. srt n'injecte dans git que `safe.directory`, par `GIT_CONFIG_COUNT/KEY/VALUE` [S7 `sandbox-utils.ts:1024-1101`]. Caches de paquets : `~/.npm/_logs` est inscriptible par commodité [S7 `sandbox-utils.ts:592-595`] ; la source ne dit rien de `~/.npm` ni de `~/.m2` au-delà. Pour les JVM, srt injecte un agent par `JAVA_TOOL_OPTIONS` et force IPv4 [S7 `macos-sandbox-utils.ts:1515-1546`, README l.844].

5. **Tester sous confinement.** srt ne détecte pas qu'il tourne déjà sous Seatbelt : aucun sondage de `sandbox-exec` dans la vérification des dépendances, qui ne contrôle sous macOS que la plateforme [S7 `sandbox-manager.ts:1242-1330`] ; `sandbox_apply` n'apparaît nulle part dans `src/` ni `test/`. Le ticket #67 constate exactement le refus que 495 a vu : `srt "srt echo hi"` donne `sandbox-exec: sandbox_apply: Operation not permitted`, journal noyau `deny(1) forbidden-sandbox-reinit` ; même chose pour `git pull` par SSH quand le `ProxyCommand` relance `srt` ; ouvert depuis le 2025-12-11, sans réponse ni correctif [S8]. La doc propose d'emboîter le bac Bash dans un conteneur ou une VM, et cite `enableWeakerNestedSandbox` pour bubblewrap dans un conteneur non privilégié (montage du `/proc` existant au lieu d'un neuf, ce qui affaiblit l'isolement) [S1 « Custom container »] [S2 « Bubblewrap fails to start inside a container »] [S3 `sandbox.enableWeakerNestedSandbox`] ; elle ne dit rien de l'emboîtement Seatbelt dans Seatbelt, alors qu'elle recommande `npx @anthropic-ai/sandbox-runtime claude` sous macOS [S1]. Déduction, non essayée : sous macOS, un Claude Code lancé dans srt verrait son propre bac Bash échouer comme dans [S8]. Côté tests de srt : les suites Linux sont sautées quand un sondage `bwrap --unshare-pid --unshare-user --proc` échoue [S7 `test/helpers/bwrap-namespace.ts`], mais la CI rejoue ce sondage sans garde pour qu'un hôte incapable « red the leg here rather than skip those arms silently » [S7 `integration-tests.yml:169-174`]. Les suites macOS s'exécutent sur des machines GitHub non confinées (`macos-14`, `macos-15-large`) [S7 `integration-tests.yml:24-29`]. L'essai en conteneur passe par une variable `SRT_E2E_DOCKER=1` et un `docker run` avec `seccomp=unconfined`, `apparmor=unconfined`, rejoué avec et sans `CAP_SYS_ADMIN` [S7 `test/docker-weak-sandbox.test.ts:1-14`, `integration-tests.yml:311-327`]. Détection côté commande : la variable `SANDBOX_RUNTIME=1` posée dans le bac [S7 `sandbox-utils.ts:758`] ; la source ne dit pas qu'elle sert à sauter des tests. Pour l'humain, la doc donne deux sondes : `touch ~/sandbox-probe` doit échouer, `curl --noproxy '*'` doit échouer [S2 « Confirm commands run inside the sandbox »].

6. **Frontière pour un bac à sable ou Docker.** « `docker` is incompatible with the sandbox » : la doc dit de le sortir du bac par `excludedCommands` (par exemple `docker compose *`), où il tourne « with your full access » après passage par le flux de permission ; elle avertit qu'un motif qui couvre un outil lisant un fichier du dépôt (le fichier compose) laisse le modèle écrire ce fichier puis l'exécuter hors bac [S2 « Run commands outside the sandbox with excludedCommands », « docker commands fail »] [S3 `sandbox.excludedCommands` : « Exclusion is a convenience, not a security boundary »]. Ouvrir `/var/run/docker.sock` par `allowUnixSockets` « effectively grants access to the host system » [S2 « Security limitations »] [S7 README l.1047]. srt pose seulement `DOCKER_HTTP_PROXY`/`DOCKER_HTTPS_PROXY` vers son mandataire [S7 `sandbox-utils.ts:913-920`]. Pour un code non fiable ou une isolation noyau, la doc renvoie à une VM, à Docker Sandboxes (microVM avec son propre démon Docker) ou à une session cloud [S1 « Virtual machine », « Choose an approach »]. Le dev container de référence ajoute un pare-feu iptables à liste blanche, qui exige `NET_ADMIN` et `NET_RAW` [S6]. Rien, dans la source, ne juge « ailleurs, sur la même révision » ce qui ne tourne pas confiné : ce qui sort du bac tourne sur l'hôte.

7. **Coût.** macOS : aucun paquet ; Linux et WSL2 : `bubblewrap`, `socat`, `ripgrep`, plus sous Ubuntu 24.04 un profil AppArmor ou `kernel.apparmor_restrict_unprivileged_userns=0` ; Windows natif non couvert par Claude Code (srt a un mode Windows « alpha » par compte local dédié) [S2 « Set up Linux and WSL2 »] [S7 README l.668-723]. Par défaut, si une dépendance manque, Claude Code exécute sans bac ; `sandbox.failIfUnavailable: true` le fait refuser de démarrer [S2 « Get started », avertissement]. Temps : un contributeur mesure 54 ms par commande avec un profil de 50 Ko passé en argument, 34 ms par fichier, et dit que Claude Code porte un profil d'environ 110 Ko [S11, PR non fusionnée]. Limites Linux : 9 000 arguments bubblewrap (environ 3 000 montages ; quatre par dépôt git imbriqué) [S7 README l.911] ; points de montage vides laissés sur l'hôte après un `SIGKILL` [S7 README l.903] [S2 « 0-byte read-only files »]. Entretien : « beta research preview », format de configuration susceptible de changer [S1 « Sandbox runtime »] [S7 README l.7-9], version 0.0.79, et la doc Claude Code date ses comportements par version (v2.1.2xx), signe de changements fréquents [S2 passim]. Pannes connues sous Seatbelt : git par SSH, outils Go et vérification TLS, `open`/`osascript`, `watchman` [S2 « Troubleshooting »].
